# Working in this repository

`pr-review-canvas` is a Node ESM CLI that opens a GitHub PR diff in a local browser canvas. The human
reads the diff and writes every review comment; the agent answers their inline questions and relays the
finished review to GitHub through one atomic POST. That division is the product, not a style choice — most
of the invariants below exist to keep an agent from taking the human's half of the job, and to keep
half-written review prose from being lost or mis-placed.

## Commands

```bash
npm run check        # the gate: build → skill --check → lint → format:check → typecheck → test
npm run build        # esbuild: dist/cli.mjs + the two browser bundles (see below)
npm run build:skill  # regenerate skills/pr-review-canvas/SKILL.md
npm test             # node --test, no framework; needs a build first
node bin/pr-review-canvas.js 219   # run from source
```

There is no CI workflow. `.github/` holds only CODEOWNERS and a PR template, so `npm run check` is the
only gate — run it before saying a change is done. Comments in the codebase that say "checked in CI" mean
`scripts/build-skill.js --check` inside that script.

`npm test` on a clean tree fails until `npm run build` has run: `test/package.test.js` asserts the `dist/`
assets exist and `test/hl-bundle.test.js` executes the built highlight worker. That is why `check` builds
first.

## Generated files — never hand-edit

| File                                  | Generated by                                                |
| ------------------------------------- | ----------------------------------------------------------- |
| `skills/pr-review-canvas/SKILL.md`    | `src/skill.js` via `scripts/build-skill.js` (**committed**) |
| `src/client/prc-client.js` (+ `.map`) | `scripts/build.js` pass 2 (git-ignored)                     |
| `src/client/prc-hl-worker.js`         | `scripts/build.js` pass 3 (git-ignored)                     |
| `src/client/prc-mermaid.js`           | `scripts/build.js` pass 4 (git-ignored)                     |
| `dist/**`                             | `scripts/build.js` (git-ignored, shipped)                   |

Two consequences worth spelling out:

- **The skill is generated from the CLI's own command table.** `createHomeOutput()` in `src/cli.js:126`
  feeds `createSkillMarkdown()` in `src/skill.js`. Change a verb or its one-line help and you must run
  `npm run build:skill` and commit the result, or `check` fails twice over.
- **`SKILL.md` is generated _and_ Prettier-checked.** Prettier formats markdown and normalizes `*em*` to
  `_em_`, so the string literals in `src/skill.js` must already emit Prettier-canonical markdown — a
  mismatch cannot be fixed in the generated file.

The browser bundles are written into `src/client/`, not `dist/`, because the asset route resolves paths
relative to its own module directory — `src/` from source, `dist/` from the package. `scripts/build.js`
copies all five assets into `dist/` for that reason; both copies must exist.

`prc-mermaid.js` is 3.4 MB — twenty times the rest of the client — so it is its own asset, fetched the
first time a ` ```mermaid ` fence appears and never otherwise. Its output is a string that goes through
`sanitizeSvg` (`src/client/diagrams.js`), which rebuilds the SVG node by node against
`src/shared/svg-policy.js`; nothing mermaid produces reaches `innerHTML`, because a diagram's source can
be a pull request comment written by a stranger.

## Architecture

Three participants, never two: the **CLI** the agent runs, a **detached local server** that owns all state,
and the **browser tab** the human reads. The CLI and the tab never speak to each other — every exchange
goes through the server, which is the only writer of anything durable. That is what makes the review
survive an agent that dies mid-poll, a tab that is closed and reopened, and a server that is replaced
under both of them.

The two halves of the API are separated by prefix, not by convention: `/api/agent/*` is addressed by
`sessionKey` (a hash of public data) and authenticated only by loopback binding; `/api/ui/*` is addressed
by a random 128-bit `accessId` and additionally requires same-origin on every non-GET. The prefixes carry
different threat models, so a route in the wrong family is a security bug, not a tidiness problem.

### Process model

`bin/pr-review-canvas.js` is a four-line shim; the published bin is `dist/cli.mjs`. `src/cli.js` (~1000
lines) owns argv, all nine verbs, and every `next_step` string the agent reads. Arg parsing, help and exit
codes come from `axi-sdk-js` through the single seam `src/axi.js`.

The CLI never runs the server in-process. `ensureServer` (`src/server-control.js`) probes `/health`, and on
a miss re-execs this same program detached — `spawn(process.execPath, [entry, "server", "--port", N])`
with stdio redirected to `~/.pr-review-canvas/server.log`, then `unref`. There is deliberately no PID file
and no lock file: `/health` is the source of truth, because a stale PID file is worse than no PID file.

Port selection is a ladder, not a constant. An explicit `PR_REVIEW_CANVAS_PORT` is an instruction and must
be obeyed or fail loudly; otherwise the recorded port in `index.json` is preferred, then `DEFAULT_PORT`
(4391, `src/paths.js:4`), then up to `PORT_LADDER_LENGTH` (10) successors. A healthy server whose
`version` **or** `build` differs is shut down and replaced — `src/build-id.js` hashes the contents (not the
mtimes) of `src/**/*.{js,mjs,css}`, so a `git checkout` that changes no bytes does not trigger a restart
while editing source does. A restart is cheap for state, which is on disk, but it does lose in-memory
armed submit tokens by design.

`src/server.js` mounts `host-guard` as the very first middleware, ahead of `express.json({limit:"2mb"})`,
so an unknown `Host` is refused before a body is ever parsed. It also owns `/health`, `/shutdown`, an idle
self-shutdown timer, and a graceful shutdown that broadcasts `chrome-reload` and then drains the store.
`src/server-routes.js` (~1700 lines, the largest file) is the whole route table plus SSE, the asset
allowlist, and the in-memory armed-token map.

### Request flow

What happens across one review, end to end:

1. `pr-review-canvas <pr>` — `normalizeArgv` rewrites a bare first token to the `open` verb, `resolvePrRef`
   turns a URL / `owner/repo#123` / bare number into a `PrRef` (shelling out to `gh pr view` in the cwd
   only for a bare number), and `sessionKey` = `sha256(canonical PR string).slice(0,16)`.
2. `assertGhReady` then `ensureServer`, per the ladder above. A session the **user** ended stays ended
   unless `--reopen` is passed.
3. `buildSnapshot` (`src/snapshot.js`) and `fetchExistingThreads` (`src/gh-threads.js`) run in parallel:
   `gh pr view` plus the files endpoint plus the whole diff, and the existing review threads. The CLI mints
   a 16-byte `accessId`, `POST`s `/api/agent/sessions`, and the server persists snapshot and threads.
4. The URL is printed and opened (unless `--no-open`). `GET /review/:accessId` renders the shell
   server-side.
5. `pr-review-canvas poll <pr>` — `GET /api/agent/poll`. With no `timeoutMs` the server long-polls: status
   200, a leading space, then one space every 15 s to hold the connection, and the JSON body at the end.
   `takeWork` drains questions, chat messages and undelivered alerts atomically; `enrichPoll` attaches
   capped code excerpts. The agent is told counts, never draft bodies.
6. The human highlights lines, asks questions, writes drafts. Drafting deliberately does **not** wake the
   agent — only questions, chat, an armed submit, and newly raised alerts do.
7. `pr-review-canvas answer <pr> --thread <id> --body-file -` — the answer arrives on stdin (backticks and
   fences do not survive a shell argument), is journalled as a `thread:message`, and reaches the tab as an
   SSE `qa-answer` with no reload.
8. The human clicks Submit → `POST /api/ui/s/:aid/submit/arm`. The next `poll` returns
   `action: submit_requested` with a raw token attached exactly once.
9. `pr-review-canvas submit <pr> --token <t>` — claim, re-validate, one atomic `POST` of the review, then
   replies one call each, then `submit/result` back to the server, which pushes `review-result` to the tab.
10. `pr-review-canvas end <pr>` marks the session ended with `endedBy:"agent"`; `stop` shuts the server
    down, politely via `/shutdown` and then by SIGTERM to the `lsof` pid.

### Session state on disk

Root is `PR_REVIEW_CANVAS_STATE_DIR` or `~/.pr-review-canvas`. `index.json` is shared across sessions and
holds the recorded port plus one row per session, which is also how an `accessId` is resolved back to a
`sessionKey` after a restart; it is written under a reserved `@index` lock because ordinary commits hold
only a per-key lock.

Each `sessions/<key>/` holds an append-only `drafts.jsonl` journal, a `session.json` fold cache, the
parsed `snapshot.json`, `threads.json` on its own clock, every `submitted/<iso>.json` result kept forever,
and a `blobs/` expand-context cache with per-file and per-session LRU caps.

`src/session-store.js` (~1000 lines) is the only writer. Every mutation funnels through `commit` →
`applyOp`, the journal is appended **before** the fold cache is rewritten, and loading means reading the
cache and replaying ops with a higher `seq`. Durability is `src/atomic-json.js`: a sibling temp file,
`fsync`, then `rename`; a torn last JSONL line is dropped on read. Thirty minutes of review prose exists
nowhere else, which is the whole reason for this shape.

### The diff pipeline

`src/diff/parse-patch.js` parses unified diffs, splitting on `\n` only, and fails closed to a `degraded`
file with zero commentable lines rather than guessing. `src/diff/index-lines.js` builds the commentable
index as merged **intervals**, so containment — not endpoint comparison — decides whether a range is
legal, and a range spanning a hunk gap is refused locally instead of 422-ing an atomic batch at GitHub.
`src/diff/model.js` states the rule that `commentableSides` is the sole authority on commentability.

`src/anchor/` is the correctness core. `anchor.js` persists an anchor together with a fingerprint (raw
text, before/after/block hashes, hunk header, blob sha). `validate.js` is the gate in front of every
submit and refuses when in doubt. `drift.js` re-anchors after a push and emits **proposals** with a status
of `unchanged | moved | ambiguous | orphaned | file-gone | file-degraded`. `suggestion.js` welds a
` ```suggestion ` block to its range via `baseLines` + `baseHash`. `src/expand.js` serves expand-context from
the blob cache, then a local clone, then `gh api contents`.

### Drafting, arming, submitting

Submit is two steps because the human and the agent are different actors. Arming (`/submit/arm`) requires
a summary for COMMENT/REQUEST_CHANGES, validates every draft, and returns 422 **before** any token exists.
`armSubmit` then mints 32 random bytes and stores only their sha256 plus a 10-minute expiry; the raw token
lives in one in-memory map, is handed to exactly one poll, and is deleted. `claimSubmit` compares with
`timingSafeEqual` and marks the claim consumed before the CLI spawns `gh`; `--dry-run` verifies without
consuming.

`src/gh.js` is the only place `gh` is spawned — `execFile`, never a shell, always `--repo` explicitly
because the server's cwd is not the user's repo. Reads live in `src/gh-fetch.js` and `src/gh-threads.js`
(REST for structure, GraphQL only for resolved/outdated, degrading rather than failing). `src/gh-submit.js`
is the only write path in the codebase and is reachable only from `submitCommand` after a successful
claim; the payload travels through a temp file via `gh --input`, never an argv full of review prose.

### Refresh after a push

`src/refresh.js` is shared by the CLI verb and the browser button: re-fetch, save the snapshot, re-anchor
everything, raise or retract alerts, return a `RefreshSummary`. Only `unchanged` — and a rename under an
identical anchor — auto-applies. Everything else becomes `state:"stale"` with a `proposedAnchor`, which is
what holds it out of the submission until the human accepts, and accepting reads the proposal from stored
state rather than from the request body. Alerts reach the agent exactly once but stay visible to the human
until retracted.

### The browser client

`src/views/page.js` renders the shell server-side, including the first `PRERENDER_FILE_COUNT` (10) file
tables and a bootstrap JSON script; remaining files mount lazily from `GET /files/:index`. There is no
iframe — isolation is a `default-src 'none'` CSP plus the rule that no PR content ever reaches `innerHTML`
unescaped. `src/shared/markdown.js` cannot represent raw HTML at all, so a `<script>` in a comment body is
un-representable rather than filtered.

`src/client/main.js` (~3400 lines) is the whole client, bundled by esbuild into `src/client/prc-client.js`.
`src/shared/` is imported by **both** the server and that bundle, which is the point: one
`diff-rows.js` renderer, one `escape.js`, one `markdown.js`, one `selection.js` clamp. Two renderers
drifting is how a comment lands on the wrong line, so eslint gives `src/shared/**` and `src/client/**`
browser globals to keep Node built-ins out.

State reaches the tab by push, over one `EventSource('/events/:accessId')` whose `open` handler re-fetches
`GET /api/ui/s/:aid` as reconnect catch-up. There is deliberately no `reload` event. The only real polling
is `GET /head` every 90 s while the tab is visible, throttled server-side to one `gh pr view` per 45 s.
Unsent text outranks freshness: a refresh reloads only when nothing is dirty and no submit is armed.

Syntax highlighting runs in a worker (`src/worker/`, bundled to `src/client/prc-hl-worker.js`) with an
explicit static map of grammar imports so esbuild can inline them; highlighting is per hunk per side, and
failure is silent — an unhighlighted diff, never a broken one.

### AXI integration

`axi-sdk-js` supplies `runAxiCli`, `AxiError`, `RESERVED_COMMANDS` and `installSessionStartHooks`, all
re-exported from `src/axi.js` and pinned exactly, so a breaking 0.x bump touches one file. `normalizeArgv`
must leave reserved commands alone, or `pr-review-canvas update` becomes `open update`. `createHomeOutput`
in `src/cli.js` is simultaneously the `home` view the SDK prints and the source of the generated skill —
see the generated-files table above.

## Invariants

Break one of these and the failure is silent or destroys someone's work, so they are asserted in tests and
argued in module headers. Read the header of a file before changing it.

**The human's prose is the most valuable thing here.**

- Never draft, reword or "improve" a review comment. There is no verb that lets an agent comment, approve
  or request changes.
- Do not add a `reload` SSE event and do not auto-reload a moved head: `applyRefreshSummary` reloads only
  when nothing is dirty and no submit is armed.
- Journal first, fold cache second (`session-store.js:575`). A new mutation means a new `applyOp` case;
  live mutation and replay must be the same code path. Unknown ops are skipped, never thrown on.
- Keep `SESSION_SCHEMA_VERSION` at 1 and widen through `normalizeSession`. Bumping it makes older builds
  refuse to load real sessions.

**Submit is gated in two steps, and the token is never persisted.** Arming validates every draft and
returns 422 _before_ any token exists; only a sha256 of the raw token is stored, with a 10-minute expiry.
The raw token lives in one in-memory map, is handed to exactly one poll, then deleted — a restart loses it
and the poll reports `submitStale` rather than an instruction that cannot be carried out. The claim is
marked consumed before `gh` runs, and a failed submit is never retried: the POST is atomic, so a failure
means nothing was posted.

**Refresh proposes; it never moves a draft.** Only `unchanged` (and a rename under an identical anchor)
auto-applies. Everything else becomes `state:"stale"` with a `proposedAnchor`, which holds it out of the
submission until the user accepts. Accepting reads the proposal from stored state, never from the request
body.

**Anchoring correctness.**

- `commentableSides` is the sole authority on whether a line can carry a comment. Expanded lines have
  none, and a `degraded` file yields zero — never "best effort".
- Range checks use interval containment, so a range spanning a hunk gap is refused up front instead of
  422-ing the whole atomic batch.
- Split diffs on `\n` only. A trailing `\r` is content; dropping it corrupts fingerprints and suggestions.
- A suggestion's anchor, `baseLines` and `baseHash` move together or the operation fails.

**One renderer, one escaper.** `src/shared/diff-rows.js` renders diff rows for the server and the browser
both; a second renderer is how comments land on the wrong line. `src/shared/markdown.js` has no node type
that can hold raw HTML — a `<script>` in a comment body is un-representable, not filtered.

**Defense in depth is by path prefix, not per route.** Unknown `Host` is 403'd before parsing (a
same-origin check alone cannot stop DNS rebinding, because a rebound page agrees with itself). Every
non-GET under `/api/ui` requires same-origin; `/api/agent/*` cannot, because the CLI sends no `Origin`, and
relies on loopback binding. Browser routes are addressed by a random 128-bit `accessId`; `sessionKey` is a
hash of public data and is guessable by design.

## Conventions

- **JSDoc-typed JavaScript**, `strict` + `checkJs`, `tsc --noEmit` over `bin/ src/ scripts/ test/`. There
  is not one `@ts-ignore` in the repo — keep it that way. Cross-file types use `import("./x.js").T`; casts
  use the inline `/** @type {T} */ (expr)` form; discriminants get `/** @type {const} */`.
- ESM, named exports only, `node:`-prefixed builtins, kebab-case filenames, `SCREAMING_SNAKE` module
  constants, `_RE`-suffixed regexes.
- Errors are `AxiError(message, CODE, suggestions[])` — a human message, a machine code, and actionable
  next steps. Subprocess failures are classified in one place, `classifyGhError` (`src/gh.js:129`).
- **Comments state rationale, not mechanics.** Every module opens with a block comment naming the failure
  it prevents; non-obvious constants carry the reason inline. Match that register.
- Prettier: `printWidth: 120`, double quotes, trailing commas. ESLint: unused args must be `_`-prefixed,
  `== null` is deliberately legal, `no-var`/`prefer-const`.

## Tests

`node --test`, no framework, everything in `test/*.test.js`. Six suites run a **real** server on
`port: 0` and talk HTTP over it; only `gh` and the PR fetch are faked. Recorded `gh api` responses live in
`test/fixtures/live/` with the re-record command in each suite's header, and hand-written diffs in
`test/fixtures/diffs.js` each carry a `why`. Suites that depend on env pin it above the imports, because
`paths.js` resolves defaults at module level.

Each suite opens with a block comment explaining why the suite exists, and individual tests get an inline
`//` rationale where the reason is not obvious. A new test should say what breaks if it is deleted.

`test/live-github.test.js` is opt-in — `PRC_LIVE=1 PRC_LIVE_PR=owner/repo#N` — and posts PENDING reviews it
deletes immediately.

## Git

Branches are `feat/<kebab-topic>`, sometimes with a milestone suffix (`feat/robustness-m8`). PRs go through
GitHub;

Commit subjects are conventional-commit types (`feat: fix: docs: test: style:`) followed by prose stating
the outcome or the cause rather than the mechanism — `fix: nothing anchored in split view, because
commentability was read off the row`. Bodies are long and argue the design: why this shape, what was
rejected, what property is now under test. Feature commits that change the count end with a bare
`510 tests.`
